# 实验一指导书：从 CSR 正确性到可信的单核性能

## 1. 实验目标

本实验围绕同一个计算问题展开：

$$
\mathbf{y}=\mathbf{A}\mathbf{x}
$$

完成实验后，你应当能够：

1. 用 CSR 格式表示稀疏矩阵并实现串行 SpMV；
2. 正确处理空行、矩形矩阵和长行等边界情况；
3. 建立 SpMV 的操作量、访存量和算术强度模型；
4. 使用预热、重复测量、中位数和绑核获得可信数据；
5. 解释数据局部性、Cache 和行工作量分布对程序性能的影响；
6. 在不改变 CSR 格式、不使用多线程的前提下优化最终实现。

实验由 `01`～`07` 七个独立目录组成。每个目录只对应报告中的一道题，某一目录的代码错误不会影响其他目录编译。

`01`～`06` 的源文件不会链接进 `07`，也不参加正式性能排行；它们用于形成最终实现所需的实验依据。

## 8. 小实验 05：相同非零元素数为什么速度不同

### 课程概念

空间局部性、Cache、工作集、间接访存。

### 阅读位置

阅读 `05/main.cpp` 中 banded 与 random 的生成和测量调用，以及 `REPORT-Q05`。本题代码无需修改。

### 先认识 banded 与 random

本题中的两种矩阵都是方阵，每行都恰好有 16 个非零元素，`values` 也按相同规则生成。两者刻意只改变 `col_idx` 的分布，以便单独观察列下标分布对 SpMV 的影响。

| 矩阵 | 每行的非零元素位置 | 计算该行时对 `x` 的访问 |
| --- | --- | --- |
| banded（带状矩阵） | 集中在行号附近。例如第 100 行主要使用第 92～107 列 | 连续读取一小段 `x`；相邻行使用的区间大量重叠 |
| random（随机矩阵） | 从全部列中随机选取 16 个互不重复的位置 | 访问可能散布在整个 `x` 中；相邻行通常没有固定的共同区间 |

例如，若暂时假设每行只有 3 个非零元素，banded 中相邻两行可能执行：

```text
第 3 行：x[2], x[3], x[4]
第 4 行：      x[3], x[4], x[5]
```

而 random 中可能执行：

```text
第 3 行：x[0], x[3], x[7]
第 4 行：x[1], x[4], x[6]
```

实现中会把 random 每一行的列下标排序，因此单行内并非毫无顺序；区别在于相邻下标之间的距离通常更大，而且相邻行不会沿着同一个窄窗口移动。banded 为保证矩阵边界处仍有相同数量的非零元素，会让开头和结尾附近的列下标环绕到另一端，这不改变本题要观察的整体访问规律。

运行时请重点观察：当 `x` 的工作集逐渐超过某级 Cache 后，两种访问规律造成的性能差异是否发生变化。不要预先假定差异的方向或大小，应以程序输出为依据。

### 操作

先记录 Cache 信息：

```bash
make info
```

再运行受控实验：

```bash
make -C 05 run
```

最大规模会分配数百 MiB 内存并运行若干秒，这是预期行为。

### 观察

两种矩阵的 `rows`、`nnz` 和每行非零元素数完全相同，受控变量只有列下标分布。将程序输出逐行填写到报告表格，不要跨规模比较绝对耗时后直接下结论。

### 完成标准

能够把吞吐率变化与工作集、Cache 容量及 `x[col_idx[k]]` 的访问规律联系起来。

### 常见错误

- 认为相同 `nnz` 必然有相同运行时间；
- 用矩阵文件大小代替运行时工作集；
- 只比较毫秒，不比较 GNNZ/s；
- 把相关性表述成未经控制实验支持的因果关系。

## 9. 小实验 06：相同行数为什么不代表相同工作量

### 这道题想让你看什么

假设要把 16 行矩阵交给 4 个执行者，每人连续处理 4 行。每个人拿到的行数一样，看起来很公平；但他们真正要做的乘加次数也一样吗？

`06/main.cpp` 会用一个普通串行程序回答这个问题。它不会创建线程，只是先把行分组，再数一数每组有多少个非零元素。

### 第一步：找到一行有多少工作

打开 `06/main.cpp`，找到 `REPORT-Q06`。CSR 第 $i$ 行从 `row_ptr[i]` 开始，到 `row_ptr[i+1]` 之前结束，所以这一行的非零元素数是：

$$
\mathrm{row\_nnz}_i=
\mathrm{row\_ptr}[i+1]-\mathrm{row\_ptr}[i]
$$

SpMV 每遇到一个非零元素，就要完成一次乘法和一次加法。因此本题用非零元素数近似表示工作量。

### 第二步：运行程序

```bash
make -C 06 clean
make -C 06 test
make -C 06 run
```

输出包含 `uniform` 和 `skewed` 两部分。先确认它们的 `rows`、`cols` 和 `nnz` 相同，再把下面这些数据填入报告：

- 每一行的 `row_nnz`；
- 空行数、最短行、最长行和平均行长度；
- 四个连续分区各自的 `local_nnz`。

`uniform` 表示非零元素比较均匀地分布在各行；`skewed` 表示少数行很长、一些行很短或为空。

### 第三步：比较四个人的工作量

如果第 $d$ 个执行者负责连续行 $[b_d,e_d)$，那么他需要处理的非零元素数为：

$$
\mathrm{local\_nnz}_d=
\mathrm{row\_ptr}[e_d]-\mathrm{row\_ptr}[b_d]
$$

程序还给出一个不均衡比例：

$$
I=
\frac{\max_d(\mathrm{local\_nnz}_d)}
{\frac{1}{p}\sum_d\mathrm{local\_nnz}_d},
\qquad p=4
$$

$I=1$ 表示最忙的执行者正好承担平均工作量；$I$ 越大，说明有人比平均值忙得越多。这里并没有真的让四个人同时计算，所以 $I$ 只是对工作量分布的描述，不是程序加速比。

回答 Q06 时，重点说明：为什么“每人 4 行”对 `uniform` 比较公平，对 `skewed` 却不一定公平。Q05 讨论的是列下标怎样影响 Cache，本题讨论的是非零元素怎样分布在各行，不要把两种现象混在一起。

### 做完的标志

- `make -C 06 test` 通过；
- 报告中的两张表已经填完；
- 能用 `row_ptr` 算出一行和一段连续行的 `nnz`；
- 能解释为什么总 `nnz` 相同、行数也相同，分组后的工作量仍可能不同。

### 允许使用的优化

以下范围只使用实验一开始前及进行期间已经讲过的内容：

| 可以做什么 | 对应课程内容 | 边界 |
| --- | --- | --- |
| 把一行的 `begin`、`end` 和数组首地址保存到局部变量 | CSR 与串行 SpMV | 不能修改矩阵和 `x` |
| 减少重复索引、重复读取和不必要的中间写入 | 访存量与 Memory Wall | 仍须完整写出每个 `y[row]` |
| 让 `values` 和 `col_idx` 保持从前到后的连续读取 | Cache 与空间局部性 | 不能重排或转换 CSR |
| 为 0、1、2、4 等短行写普通 C++ 快速路径 | 行长度与工作量分布 | 必须保留处理任意行长的通用路径 |
| 用普通 `for` 循环做 2 路或 4 路展开，并正确处理尾部 | 流水线与指令级并行 | 不能假定每行长度固定 |
| 使用 2 个或 4 个局部累加器后再合并 | 超标量与指令级并行 | 加法顺序改变后仍须通过误差检查 |
| 根据当前行长度选择上述串行路径 | 任务工作量差异 | 只能依据当前输入，不能缓存特定矩阵 |

Release 公开测试、性能测试和正式评测的优化等级均固定为 `-O2`，并使用 `-march=native`。`make debug-test` 采用 `-O0`，用于 ASan/UBSan 检查，不参加性能排行。编译器可以自动优化普通 C++ 循环，也可能自动生成 SIMD 指令；学生不需要也不允许直接编写硬件指令。学生不得自行更换优化等级或追加编译选项。

执行前面的 baseline 或 optimized 命令时，程序都会自动加载该矩阵。如果文件缺失或无法读取，基准测试会直接报错，而不是跳过该项。数据来源、许可证和校验值见 `data/README.md`。

## 11. 正式评测说明

### 11.1 正确性评测

正式评测从提交中提取 `07/spmv_student.cpp`，与干净框架一起编译。使用固定编译参数：

```text
-std=c++17 -O2 -march=native -DNDEBUG
-Wall -Wextra -Wpedantic
```

正确性使用以下混合容差：

$$
|y_i-y_i^{ref}|\le 10^{-5}+10^{-4}|y_i^{ref}|
$$

60 分正确性按下表组成：

| 检查项 | 分值 |
| --- | ---: |
| 构建与固定接口 | 5 |
| 基础 CSR | 15 |
| 空行、矩形矩阵和极端行长 | 15 |
| 随机及真实矩阵 | 20 |
| 越界、输入完整性和重复调用 | 5 |

评测还会检查 NaN/Inf、`y` 越界写入、输出是否全部覆盖、矩阵或 `x` 是否被修改，以及更换 `x` 后是否错误复用旧结果。全局状态、静态缓存、多线程、被禁止的库和指令也会被检查。隐藏正确性必须全部通过，否则性能分为 0。

### 11.2 云端性能测试数据

学生本地性能测试与云端正式性能评测使用不同的数据集。云端测试数据由评测平台提供，学生无需下载或准备。

### 11.3 计时与排名规则

- 只计 `spmv_student` 函数执行时间；矩阵读取、生成、内存申请和验证均排除。
- 使用固定编译器和 `-O2 -march=native`，独占并绑定一个物理 CPU 核心。
- 预热 3 次，自动增加迭代次数，使每批不少于 250 ms。
- 测量 7 批并取单次耗时中位数，循环使用 8 组不同的 `x`。

设提交 $i$ 在矩阵 $d$ 上的单次内核耗时为 $T_{i,d}$ 秒，其吞吐率为：

$$
g_{i,d}=\frac{\mathrm{nnz}_d}{10^9T_{i,d}}
$$

其中 $g_{i,d}$ 的单位为 GNNZ/s。设云端性能测试数据集为 $D$，综合性能指标采用各矩阵吞吐率的几何平均：

$$
G_i=\exp\left(\frac{1}{|D|}\sum_{d\in D}\ln g_{i,d}\right)
$$

平台同时提供两个排行榜页面：

#### 参考排行榜

平台参考实现与有效学生提交一起排名。令该页面中最高的综合性能指标为 $G_{\max}^{\mathrm{ref}}$，页面显示的参考性能分为：

$$
P_i^{\mathrm{ref}}=20\frac{G_i}{G_{\max}^{\mathrm{ref}}}
$$

平台参考实现只用于性能对比，该页面的分数不计入课程成绩。学生提交仍然禁止调用外部计算库。

#### 正式排行榜（仅包含学生提交）

该页面只包含有效学生提交。令全班最高的学生综合性能指标为 $G_{\max}^{\mathrm{student}}$，正式性能成绩为：

$$
P_i=20\frac{G_i}{G_{\max}^{\mathrm{student}}}
$$

两个页面均展示排名、$G_i$ 和按各自榜首计算的当前性能分；截止后只以正式排行榜计算最终成绩。

性能分保留两位小数，最高 20 分。正式排行榜前三会进行规则检查并独立复测三轮；同一有效提交连续复测的综合性能波动目标不超过 3%。
